# The SPLICE detector: model, training, calibration, evaluation and export

This directory holds the **SPLICE object detector** of SPLICE-V (SPLICE-B on YOLO26-S in its
seven readout arms, deployed arm (e): the confined forecast with the exposure discount and the
exact residual) and everything that trains it, measures the paper's `train` channel and turns
it into the integer contract of the VE2302 implementation:

```
splice_det/   PyTorch model, training, calibration, QAT, evaluation, diagnostics, export (+ numpy core)
hpc/          the Arrhenius suite: launcher, runner, dataset download, guide (hpc/README.md)
export_spec.json   what an export must supply (generated by tools/make_export_spec.py)
../artifacts/trained/synthetic_arm_e/   a complete export from the synthetic-scene run (provenance S)
```

The model code is written for this repository from the paper (section 2) and the roadmap;
every place where the paper is silent is a recorded design decision (below).

## The detector in brief (SPLICE-V section 2)

YOLO26-S keeps its backbone and its detection head; its native neck is replaced by the SPLICE
neck (SPLICE-B).  At 640 x 640 input the neck works on the P3/P4/P5 lattices (80^2, 40^2, 20^2)
with 64 latent channels, 48 transported and 16 protected:

1. **Preserve.**  Supervised cell heads (edge affinities pi, purity q, eligibility e, thin
   structure t, gate g, a monotone beta chain); lazy walks P = 1/2 I + 1/2 S^-1 (I + W) with
   4, 8 and 12 steps; signed bands Z_j = (A(beta_j) - A(beta_j+1)) X; typed mixing R_w.
2. **Coarsen.**  1,600 P4 anchors plus 256 reserved P3 anchors (farthest-point sampling),
   guarded average linkage on the Chebyshev-2 window in certified rounds under a counted work
   budget (Lemma 2), at most 256 fragments, hard memberships M, restriction H = R X.
3. **Exchange.**  Per-anchor box hypotheses fused by precision per fragment, a Mondrian
   conformal Mahalanobis test (delta = 0.01) -> the admissible set C_f shared by the forecast
   and the exchange; Eq. (1) partner posterior, Eq. (2) trust solve with need zeta in [0, 1]
   (at most 8 sources), one-hop innovation dH.
4. **Route.**  The readout arm.  Deployed arm (e): confined forecast Eq. (3) with logits
   <K_f, K_g> / sqrt(d) + <Psi nu_f, Psi nu_g> + log(1 - xi_g) over C_f plus a null option,
   shrink alpha = (1 - 2^-4) sigmoid, innovations clipped to 64 LSB, through a zero-initialised
   injection map; X'^s = X^s + M dHhat + R_w^perp; a bottom-up path G; readout
   cls_in = Pi X'' + M r O (r = dH - dHhat), box_in = Q X''; class score p = sigma(l) gamma.

The **exposure budget** xi_g = min(1 - eps, 2 kappa_g chi_g), chi_g = sum_j nu_gj tau_gj,
discounts a source in the forecast by what its bands can carry across an ownership boundary
(Lemma 3).

Readout arms (Table 7; `config.ARMS`): every arm keeps preserve, coarsen, the supervised
heads, the bottom-up path and the Pi / Q split, and differs in where the transport enters.

| arm | injected before the bottom-up path | class head reads | exchange at inference |
|---|---|---|---|
| a | exact dH | Pi X'' | yes |
| b | nothing | Pi X'' + M dH O | yes |
| c | nothing | Pi X'', class logits + M (dH o) | yes |
| d | free forecast softmax(K K^T / sqrt(d)) V O_F | Pi X'' + M (dH - dHhat) O | yes |
| e | confined forecast (deployed) | Pi X'' + M (dH - dHhat) O | yes |
| f | confined forecast | Pi X'' | no (training target only) |
| g | nothing | Pi X'' | no |

Forecast descriptors of arm (e) (`config.DESCRIPTORS`): `bands` (deployed), `no_discount`,
`learned_mix`, `lowpass`, `blind`, `local`, `single_step`.

Training objective: L = L_det + 0.1 mean (dHhat - sg(dH))^2 + 0.05 || Q [G(X' + M v) - G(X')] ||^2
+ L_aux (supervised neck heads), with L_det YOLO26's own criterion.  No gradient passes
through the linkage: memberships, partner lists, active sets and admissibility decisions are
constants of the backward pass; gradients reach the exchange through Eq. (1) and the
optimality system of Eq. (2).

## Where the detector is trained

| run | command | data | provenance | weights / coefficients |
|---|---|---|---|---|
| synthetic qualification (done) | `python -m splice_det.toytrain` | synthetic scenes of `reference/splicev_ref/toy.py` | S | `artifacts/trained/synthetic_arm_e/` |
| image training (Arrhenius) | `sbatch run_splicev.sh` (`hpc/README.md`) | COCO 2017, CrowdHuman | T | `checkpoints/<suite>/<run>/{trained,calibrated,qat}.pt`, exports and tables in the suite folder |

**Synthetic run (this repository).**  800 training, 160 validation, 320 calibration and 160 test
scenes (disjoint seeds).  The forecast maps W_K, U, u0, u_alpha, O_F are trained against the
exact integer exchange; the class head and the residual maps are trained on cell ownership;
the gate thresholds, partner prior and band exponents are calibrated on the calibration scenes
and written to a model manifest whose generated sources the training then runs under.  On the
test scenes the residual r = dH - dHhat drops from 895 LSB^2 (no forecast) and 395 LSB^2
(initial maps) to 175 LSB^2, |r| >= 16 LSB from 37% to 17% of the entries, and the trained heads
run bit-exactly through the AIE units and PL engines of the toy slice (4/4 scenes).  The scenes
carry no image content, so box hypotheses and class evidence are not learnable there: these
artifacts qualify the training -> calibration -> export -> integer -> device chain, they are
not a detector.  The run uses the forecast of the integer reference, which has no exposure
discount yet (open items).

**Image training (Arrhenius).**  The suite (`hpc/`) trains every registered run from the
published YOLO26-S weights (new neck), calibrates on the calibration split, runs the
quantization-aware training of arm (e), evaluates every model with and without the gate,
measures the train-channel quantities and decides the declared tests 2, 3, 9, 10 and 12 with
a two-level bootstrap.  Its smoke scale is the first execution of this package's PyTorch code
on a GPU; nothing image-trained is committed to the repository yet.

## Design decisions of the model (the paper is silent)

| id | decision |
|---|---|
| DM-01 | Ownership: a cell belongs to the smallest box containing its centre.  Targets: e = g = owned; q = 1 / (boxes containing the centre); t = owner's short side below two cells; pi_k = same owner as neighbour k; linkage pair scores by the same rule on the window. |
| DM-02 | Cell heads: conv3x3-BN-SiLU then a zero-initialised 1x1 (16 channels: 8 pi, q, e, t, g, 4 beta logits); beta_k = c_k / (1 + c_4), c = cumsum(softplus(u) + 1e-4). |
| DM-03 | Linkage pair scorer: 16-channel embeddings of the P4 and P3 latents, scaled dot products plus a learned bias; probabilities are quantized to u8 codes and the integer reference makes the linkage decisions (outside autograd), so DFP32, Db and M share fragments for the same codes. |
| DM-04 | Box hypotheses: an MLP on each anchor's latent gives softplus distances (x 2 x stride) to the box sides from the anchor centre and four log-precisions per stride^2; Gaussian NLL in stride units, weight 0.05.  Hypotheses are computed before the exchange ("early"). |
| DM-05 | Trust heads: need = softplus, rho = softplus + 1e-3, Phi = 0.25 tanh of a linear map of the pre-exchange state H_f, so Phi is available before the solve (closes the roadmap 2.2 dependency in this model). |
| DM-06 | Evidence: a symmetric scorer s_fg = <S H_f, S H_g> / sqrt(32), clamped to the posterior's input range. |
| DM-07 | Exchange values: VO_T = O_T H (own map, separate from the forecast's O_F). |
| DM-08 | Typed mixing R_w = sum_j gain_lj Z_j with zero-initialised gains; fusion blocks scale the eight lateral taps of a 3x3 mixing by the affinities they cross. |
| DM-09 | Probe of the sensitivity term: fragment-constant delta ~ N(0, (4 LSB)^2) per transported channel. |
| DM-10 | Calibration: gate pairs are same-majority-owner fragment pairs; strata by fragment count (32, 96, 192), pooled when a stratum has fewer than 200 pairs; prior with +0.5 smoothing; band exponents floor(log2(127 / q99.99)). |
| DM-11 | QAT: neck activations int8 at the transport LSB (1/16), bands at LSB 2^-e, dHhat/dH symmetric +-127, neck linear weights int8 with per-tensor power-of-two scales; backbone/head activations int8 with calibrated power-of-two scales, weights quantized after BN folding at export. |
| DM-12 | Arms: all seven keep the Pi / Q readout split.  Arm (a) injects the exact dH through the zero-initialised map before the bottom-up path and its class head reads Pi X'' only; arm (c) adds M (dH o) to every class logit of a cell, o a zero-initialised map per level; arm (d) is softmax(K K^T / sqrt(d)) V O_F over all other fragments of the image, without admissible set, null option, shrink or clip; arm (f) runs the exchange only in training, as the forecast's target. |
| DM-13 | Exposure budget: kappa_g is the largest one-step leaving probability of the lazy walk over the fragment's cells and the three levels; nu_g are the fragment's band energies normalised over the 12 (level, band) entries; tau_gj is the largest diffusion-time weight of band j over the fragment's cells; chi_g = sum nu tau; xi_g = min(1 - 2^-4, 2 kappa_g chi_g).  The discount is a constant of the backward pass. |
| DM-14 | Descriptor variants: `learned_mix` learns the coefficients of the same walk powers (start: the nominal chain 0.2, 0.4, 0.6, 0.8); `lowpass` reads the stack A(beta_j) X; `blind` sets pi = q = 1 in the walk; `local` replaces the bands by channel-shared 3 x 3 stencils of equal cost; `single_step` keeps the one-step stencil only. |
| DM-15 | Gradient path: the linkage, the partner lists, the screened active sets and the admissibility decisions are computed outside autograd; on these fixed decisions the posterior (prefix / suffix recursion) and the trust solve (linear system of the active set) are differentiated exactly. |
| DM-16 | Recipe: 50 epochs from the published YOLO26-S weights, batch 16, 640 x 640, SGD (momentum 0.937, Nesterov), learning rate 0.01 for the neck and 0.001 for backbone and head, 1,000 warm-up iterations then cosine to 1%, weight decay 5e-4 on weights, EMA, bf16 autocast outside the neck, Ultralytics augmentation with mosaic closed for the last 10 epochs.  QAT: 12 epochs at a tenth of these rates, no EMA, no mosaic.  YOLO26-S is trained by the same loop for the baseline rows. |
| DM-17 | Data roles: the calibration split is held out of training by a hash of the file name (1/24 of COCO train2017, 1/12 of CrowdHuman train); the validation sets are used for evaluation only. |
| DM-18 | CrowdHuman: full-body boxes; training labels and the evaluation's ground truth are clipped to the image; ignore regions follow the official matching rule; heavy occlusion is a visible ratio below 0.65. |
| DM-19 | Accuracy "under the manifest": the QAT model with every rounding site of the manifest active stands in for the integer model M in the train channel; M itself is the integer reference. |
| DM-20 | Skip rule: the skipped share of class-head blocks at theta_det = 0.25 is reported for blocks of 1 x 1, 2 x 2 and 4 x 4 cells. |

The integer reference (`reference/splicev_ref`) remains the definition of model M; the float
operations follow its conventions (neighbour order, telescoping bands, unassigned cells, null
option, clip) so that an export maps onto it.

## From the detector to the device

| detector stage | torch (`splice_det`) | integer reference (`reference/splicev_ref/`) | VE2302 engine |
|---|---|---|---|
| walks, bands | `ops.walk_powers`, `ops.bands` | `walk.py` | AIE STENCIL unit |
| reserve anchors | `linkage_bridge.reserve_job` | `reserve.py` | PL `sv_reserve` |
| certified linkage, fragment ids | `linkage_bridge.linkage_job` | `linkage.py` | PL `sv_linkage` |
| restriction, detail, synthesis, class band | `ops.restrict`, `ops.fill`, `ops.class_band` | `membership.py` | AIE SEGOPS units |
| descriptor nu, modulation | `ops.descriptor_nu`, `ops.modulated_taps` | `walk.py`, `units.py` (TAPMOD) | AIE TAPMOD units |
| conformal test -> C_f | `ops.fuse_hypotheses`, `ops.admissible` | `gate.py` | PL `sv_gate` |
| confined forecast Eq. (3) | `ops.forecast` (+ `ops.exposure_discount`) | `forecast.py` (no discount yet) | AIE HEAD (FORECAST) unit |
| posterior Eq. (1), trust solve Eq. (2) | `exchange_float.exchange`, `exchange_torch` | `posterior.py`, `trust.py`, `exchange.py` | PL `sv_exchange1` |
| priority products, dV | `exchange_float.exchange` | `exchange.py` | AIE PERMUTE + PL `sv_exchange2` |
| residual, class scores, candidates | `SpliceNeck` readout, `SpliceYOLO.decode` | `readout.py` | AIE GEMM + HEAD (SCORE) units |
| backbone and neck convolutions | Ultralytics / `neck.py` | `units.py` (CONV, GEMM) | AIE CONV/GEMM units |

The hardware (**H**) must match M bit for bit at the six boundaries (ids, G, H3' sources, dV,
logits, candidates).

|---|---|---|

| DFP32 | a readout arm, float32 (`SpliceYOLO`, exact float exchange) | P2: DFP32 vs M |

## Open items

- **First GPU run.**  The PyTorch training and inference code has run forward-only on the
  numpy stand-in; its first execution on real torch, Ultralytics and the datasets is the smoke
  scale of the Arrhenius suite.
- **Exposure discount on the device.**  The integer reference, the generated sources and the
  AIE forecast unit implement Eq. (3) without log(1 - xi_g); the integer format of the budget
  (kappa, tau, the logarithm) is not in the contract yet.  An export of a model trained with
  the discount lists it under `pending_for_the_device` and stays non-deployable.
- **Hardware track vs the current draft.**  The contract, the analytical audit and the VE2302
  sources of this repository follow an earlier draft of SPLICE-V; the current draft changes
  analytical values there (for example the logic's DSP58 count) that have not been carried over.
- **QAT forward pass.**  The paper's QAT runs the integer reference as its forward pass; here
  the forward pass is the float model with the manifest's rounding sites (DM-19).
- **Full-detector programs (G10).**  The export carries BN-folded int8 weights and float biases
  of every live layer; the program generator that turns them into AIE CONV/GEMM unit programs,
  int32 biases and shifts, and the integer format of the hypotheses for `sv_gate`, belongs to G10.
- **Deployability (G08).**  Exports stay non-deployable until the partition catalog exists.

## Producing the deployable manifest

```bash
# 1. a run's export: artifacts/trained/<run>/manifest.model.json extends manifest.dev.json and
#    replaces every SYN value with a calibrated/model value (provenance T)
python3 tools/check_contract.py --manifest artifacts/trained/<run>/manifest.model.json
# 2. once the open items and G08 are closed: "deployable": true, then
python3 tools/check_contract.py --manifest contracts/manifest.model.json --require-deployable
python3 tools/generate_sources.py --manifest contracts/manifest.model.json --out generated
make test host-cpp
```

`export_spec.json` is generated by `tools/make_export_spec.py`; `make check-generated` fails if
it is stale.
